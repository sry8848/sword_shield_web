# 02 工程与编码规范

## 分层与依赖方向

| 职责 | 约束 |
| --- | --- |
| Controller（接口层） | 接收请求，做输入格式校验，映射 HTTP DTO 并调用用例。数据库实体留在服务内部。 |
| Application（应用层） | 编排用例、授权检查、事务与跨边界调用。需要事务的业务写入从用例入口划定边界。 |
| Domain（领域层） | 维护业务规则、不变量和状态转换。领域规则独立于 HTTP、持久化框架和其他服务的实现。 |
| Infrastructure（基础设施层） | 实现数据库访问、外部客户端及消息等适配。将数据库实体和框架类型留在适配边界。 |

Controller 依赖 Application，Application 调用 Domain。业务需要隔离外部依赖时，在业务侧定义所需契约，由 Infrastructure 实现。包和类随实际职责组织，避免仅为目录对称提前建空包、空接口或一一对应的包装层。公共库仅放与具体领域无关的通用能力，业务实体和策略由所属领域维护。

## API 契约与异常

- 对外接口按仓库 [OpenAPI](../../../xihu-jian-frontend/openapi/openapi.yaml) 约定实现。路径、方法、DTO、ID 表示、时间格式、分页、响应结构、状态码和错误码均查该契约。接口变更先评审并更新 OpenAPI，再修改接口实现。
- 在接口边界校验请求。查询排序使用允许的字段集合。按明确时区转换业务日期，数据库中的时间点按 UTC 保存。
- 普通 JSON 成功响应继续使用 `ApiEnvelope<T>`，包含 `code`、`message`、`data`、`traceId` 和 `timestamp`。成功码为 `SUCCESS`，`message` 仅供辅助展示。
- API 错误响应采用 [RFC 9457 Problem Details](https://www.rfc-editor.org/rfc/rfc9457.html)，使用 Spring 原生 `ProblemDetail` 和 `Content-Type: application/problem+json`。响应使用实际的 4xx 或 5xx HTTP 状态，禁止用 HTTP 200 包装失败。

### 错误响应字段

| 字段 | 规则 |
| --- | --- |
| `type` | 固定为 `about:blank`。 |
| `title` | 对应 HTTP 状态的标准简短说明，可本地化。 |
| `status` | 必须与实际 HTTP 状态一致。 |
| `detail` | 本次错误的具体说明，必须可安全公开。 |
| `instance` | 可选。仅在有实际错误实例 URI 引用时返回。Spring 默认可能填入请求路径，项目对外响应应省略这类默认值。 |
| `code` | 必填的项目扩展字段，是唯一用于识别业务错误类型的稳定字段。 |
| `traceId` | 必填的项目扩展字段，取自真实请求追踪上下文。 |
| `timestamp` | 必填的项目扩展字段，由服务端生成，采用带时区的 ISO 8601。 |
| `errors` | 可选的项目扩展字段，仅用于字段校验。每项包含 `field`、字段原因 `code` 和安全说明 `detail`。 |

`title` 和 `detail` 供人阅读。禁止返回泛化的 `details` 对象。错误响应不得包含异常堆栈、类名、SQL、内部服务地址、密码、Token、Cookie 或其他敏感数据。对未知内部异常返回通用说明。

### 错误分类与状态

| HTTP 状态 | 适用场景 | 错误码 |
| --- | --- | --- |
| 400 | 请求格式或参数错误 | `INVALID_ARGUMENT` |
| 401 | 未认证，或所需认证凭证无效或过期 | `UNAUTHENTICATED`、`ACCESS_TOKEN_EXPIRED`、`REFRESH_TOKEN_EXPIRED` |
| 403 | 已认证但无权访问，或认证接口的浏览器请求来源未获授权 | `FORBIDDEN` |
| 404 | 目标资源不存在 | `RESOURCE_NOT_FOUND` |
| 405 | 目标资源不支持该请求方法 | `METHOD_NOT_ALLOWED` |
| 409 | 业务状态冲突 | `BUSINESS_CONFLICT` 或 OpenAPI 已定义的具体错误码 |
| 413 | 请求体超过适用的大小上限 | `PAYLOAD_TOO_LARGE` |
| 415 | 请求体媒体类型不受支持 | `UNSUPPORTED_MEDIA_TYPE` |
| 422 | 参数格式正确，但不满足业务规则 | `BUSINESS_RULE_VIOLATION` 或 OpenAPI 已定义的具体错误码 |
| 429 | 请求超过适用的频率限制 | `TOO_MANY_REQUESTS` |
| 500 | 未预期的内部错误 | `INTERNAL_ERROR` |
| 502 | Gateway 收到无效的上游响应 | `BAD_GATEWAY` |
| 503 | 目标服务暂不可用 | `SERVICE_UNAVAILABLE` |
| 504 | Gateway 等待上游响应超时 | `GATEWAY_TIMEOUT` |

顶层错误码采用大写下划线命名，在整个项目内保持唯一、稳定。同一码在各服务中表示相同语义。保留已有业务码及其 HTTP 状态，新增错误码时先在 OpenAPI 记录适用场景和 HTTP 状态。接口只声明适用的错误响应，路由级或基础设施级错误按实际生效范围使用公共响应定义。

### 处理职责

- Spring MVC 使用 `@ControllerAdvice` 和 `ResponseEntityExceptionHandler` 统一处理 MVC 异常，并在 HTTP 边界将业务失败映射到错误码和状态。
- Servlet 环境的 Spring Security 使用 `AuthenticationEntryPoint` 处理未认证，使用 `AccessDeniedHandler` 处理权限拒绝。WebFlux 环境使用对应的响应式安全入口与拒绝处理器。
- Spring Cloud Gateway 使用 WebFlux 的全局异常处理机制处理网关自身异常及上游调用失败。下游已经返回符合契约的 Problem Details 时，透传其 HTTP 状态、媒体类型与响应体。
- Common 仅提供跨服务确需共享的错误码和响应通用能力，禁止引入 MVC 或 WebFlux 依赖。Domain 表达业务失败及其原因，保持独立于 HTTP 状态、Spring MVC 和 WebFlux。

各处理边界均遵循同一 Problem Details 契约。

## 数据访问与迁移

- 表和列用 `snake_case`，Java 字段用 `camelCase`。同一模型采用一致的主键策略。业务记录明确保存账号、场次、大会等适用归属，归属字段由业务服务依据可信数据写入。
- 各服务维护自己的版本化数据库迁移，已执行的迁移只通过新增版本演进。生产环境禁止自动改表及加载演示数据。
- 业务唯一性与幂等约束应落实到数据库。写入一致性见 [事务与一致性](01-总体架构与数据所有权.md#事务与一致性)，受保护数据的读写见 [数据库中的范围约束](03-权限数据范围组织租户审批.md#数据库中的范围约束)。
- 密码、会话令牌及凭证按用途保存必要的安全表示或元数据。禁止把明文密码、完整 JWT 或完整核验令牌写入业务表。

## 配置、部署与可观测性

- 环境相关配置外置，真实密钥与密码从环境或密钥系统取得。演示凭证和开发默认值仅用于本地。固定构建依赖版本，升级须验证整套依赖的兼容性。
- 区分存活与就绪检查。为实际依赖的下游设置超时并按需限制请求量。新增中间件应服务于已明确的业务或运行需求。
- 在请求入口接续可信追踪上下文或创建新的追踪上下文，并在 Gateway 和下游服务间传播。响应与日志使用该上下文中的 `traceId`，禁止在构造响应时临时生成无法关联日志的 UUID。建议使用 Spring Boot Actuator 和 Micrometer Tracing，按需通过 OpenTelemetry 导出。
- API 错误响应与服务端诊断日志分离。日志记录 `traceId`、服务、操作、耗时和结果。未知 500 异常在服务端记录完整堆栈，普通业务异常通常只记录必要上下文。脱敏手机号等个人数据，禁止记录密码、完整 Token、Cookie 或凭证二维码原文。
- 关键状态变化记录操作人、时间、资源、前后状态与必要原因。权限拒绝、跨租户尝试和重复核验应可追溯。

## 测试与发布

| 层次 | 验证内容 |
| --- | --- |
| 单元测试 | 覆盖适用的业务规则、状态转换、授权策略及拒绝行为。 |
| 数据库集成测试 | 使用实际选用的数据库验证迁移、事务回滚、约束及复杂授权查询。对并发报名、重复核验等存在竞争的操作验证原子性与幂等。 |
| 安全测试 | 验证未认证、无操作权限、错误资源范围和适用的租户隔离。覆盖相关的详情、列表、统计、导出和批处理，断言响应及数据库结果符合预期。 |
| 契约测试 | 对照 OpenAPI 校验代表性的成功和错误响应。发布前运行适用的单元、集成、安全和契约检查。 |
