# 03 认证、授权、租户、组织与审批

## 认证和授权职责

MVP 以[登录业务设计](../../../docs/设计/登录设计/登录设计_2026-11-25_10-40.md)与[技术设计](../../../docs/设计/登录设计/登录与会话技术设计_2026-11-25_10-40.md)为准。Portal 保持现有 JWT 安全链；Admin 由 Identity 的 Spring Session Redis 托管，Gateway 每次同步 ForwardAuth 校验，不缓存当前角色。业务服务仅接受可验证 Gateway 服务身份的可信连接和由其重建的身份头，拒绝绕过网关的伪造请求。前端菜单不是授权边界。

| 固定角色 | 允许的 MVP 操作 |
| --- | --- |
| SUPER_ADMIN | B27 账号/固定角色分配和必要系统配置 |
| EVENT_OPERATOR | B03 场次、议程、发布/下线；B04 报名；B21 基础运营统计 |
| CHECKIN_STAFF | B05 授权场次核验及必要核验记录，不能编辑活动 |

兼任角色的明确允许操作取并集，未授予即拒绝。SUPER_ADMIN 不自动获得其他角色权限。角色映射由所属业务服务固定维护，无动态配置。核验员场次授权由 Activity 管理，普通运营不做场次范围分配；领取点随对应业务启用。提交后新开始的权限检查必须读取当前权威数据，账号/角色读取 Identity 主库，核验范围读取领域主库。

## 安全审计事件

- Identity 记录角色分配/撤销、账号禁用/启用的操作者、目标、前后变化和时间。保留 Portal 已有安全审计，Admin 登录失败等使用必要安全诊断日志，需持久化的其他安全事件按实际风险确认。
- Activity 记录现场核验人员、时间、对象及结果；发布、下线、重要报名状态变更按领域规则记录。场次授权变更由维护授权的业务域记录。重要变更与审计同本地事务提交；普通浏览和查询不持久化审计。
- 审计归属和保护见[安全审计持久化](02-工程与编码规范.md#安全审计持久化)。

## 资源范围语义

普通用户本人资源仍按真实业务归属校验。会务运营管理当前大会活动和报名；现场核验员按账号与场次的明确关系校验，集合为空则无核验权限。核验授权不等于编辑或全量报名读取授权。不实现通用范围引擎、字段级授权、角色继承或显式拒绝。

## 数据库中的范围约束

- 在数据库查询层落实适用的数据范围。详情仅在受控范围内查找，或从安全边界内读取判定所需的可信归属后完成鉴权，再返回数据。列表在分页、计数和聚合前应用范围，导出与统计遵守对应读取范围。
- 更新、删除和批处理必须约束实际操作的记录集合，确保授权检查和写入之间不会因并发变化而越权。
- 范围条件使用领域认可的关系和参数化查询。禁止把任意 SQL 字符串当作授权规则，或先查全量数据再在应用层做范围过滤。审查自定义 JOIN、原生查询、批量写入和逻辑删除等可能绕过常规过滤的路径。

## 启用多租户后的约束

当前 MVP 不启用多租户，不添加租户字段或隔离引擎。未来有明确业务需求再评审。

## 启用组织与审批后的约束

当前 MVP 不启用组织树、部门继承或通用审批引擎。未来按实际业务单独设计。
