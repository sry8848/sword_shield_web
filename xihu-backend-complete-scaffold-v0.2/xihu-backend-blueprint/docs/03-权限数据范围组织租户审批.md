# 03 认证、授权、租户、组织与审批

## 认证和授权职责

- Identity 负责认证、会话及 RBAC 配置。业务服务从经验证的身份取得操作人，负责本服务的功能权限和资源范围校验。管理接口绕过网关访问时也须执行相同的保护。前端菜单和按钮只反映权限，稳定的业务权限码独立于路由和菜单。
- 对受保护的业务操作，先建立可信身份与适用的租户边界，再确认功能权限和资源范围，最后校验业务状态。缺少可信上下文、授权不可用、策略无法解释或无允许授权时，拒绝访问。
- 角色分配决定操作权限。数据范围需与资源类型及操作关联，场次核验授权不会自动授予同一场次的编辑权限。多个角色对同一操作与资源类型的有效允许范围默认取并集，始终受租户边界约束。显式拒绝及其他来源的冲突规则见 [待确认事项](11-现有前端OpenAPI契约差异与冻结项.md)。
- 权限及范围授权的变更、撤销应可审计，并能立即或在明确的时限内生效。长期令牌中的静态权限快照不能作为唯一依据。

## 资源范围语义

| 范围 | 约束 |
| --- | --- |
| ALL | 允许访问当前安全边界内该操作覆盖的资源。 |
| SELF | 按领域从可信业务数据取得的归属判断。例如报名记录 R9 属于 U1，判断使用报名的账号归属 U1。客户端提交的用户标识和报名 ID 都不能代替该归属。 |
| ASSIGNED | 按已授权的资源集合或领域关系判断。集合为空时范围为空。 |
| NONE | 无可访问资源。 |

各领域解释本领域资源的授权关系。Activity 可按已分配场次授权核验，并通过场次关联限制报名列表。Identity 解释账号本人关系，涉及某场次参会人的访问条件由相关业务域提供可信关系。Content 和 Customer Service 分别解释内容归属和工单分配。这些是语义示例，具体范围随业务需求确认。

共享同一职责和资源范围的账号可使用角色级授权。组织或个人来源只在对应需求出现后引入，落地前明确来源、适用范围、合并及撤销规则。

## 数据库中的范围约束

- 在数据库查询层落实适用的数据范围。详情仅在受控范围内查找，或从安全边界内读取判定所需的可信归属后完成鉴权，再返回数据。列表在分页、计数和聚合前应用范围，导出与统计遵守对应读取范围。
- 更新、删除和批处理必须约束实际操作的记录集合，确保授权检查和写入之间不会因并发变化而越权。
- 范围条件使用领域认可的关系和参数化查询。禁止把任意 SQL 字符串当作授权规则，或先查全量数据再在应用层做范围过滤。审查自定义 JOIN、原生查询、批量写入和逻辑删除等可能绕过常规过滤的路径。

## 启用多租户后的约束

- 租户是数据隔离边界。共享环境从可信认证建立当前租户上下文并验证有效成员关系，客户端传入的租户标识只能用于选择，不能直接授予访问权。角色、组织继承和超级管理员标识均不得在业务服务中绕开隔离。
- 共享表中的租户数据须有明确归属，在读取、写入、索引与唯一约束、跨表关联中维护隔离。共享应用使用独立数据库时须验证数据源路由与迁移隔离。独立部署可用实例和存储边界隔离。
- 缓存、文件、消息、后台任务和统计与数据库一起验证隔离。启用时至少验证两个租户，覆盖准确 ID、伪造头和批量访问等反向场景。预留字段只表示数据模型意图。

## 启用组织与审批后的约束

- 组织表达部门、项目组及成员关系，可参与管理范围、角色继承与审批人解析。组长管理成员同时要求操作权限和组织范围。启用时验证组织树环路、交叉任职和调组撤权。
- 关键发布动作采用显式业务命令。审批对明确且冻结的业务修订版本生效，保留已发布版本，记录办理人及操作历史。审批结果通过受保护的业务用例推进状态，业务域再次校验状态和权限，重复回调不得重复推进。
- 组织、租户与审批只在实际业务启用时落地。候选实现见 [实现参考](07-参考开源实现与取舍.md)。
