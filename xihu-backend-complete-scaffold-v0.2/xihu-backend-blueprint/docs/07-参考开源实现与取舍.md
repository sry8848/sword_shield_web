# 07 实现参考与历史取舍

本页收录可选方案。选用前按真实用例验证，优先从当前业务需要的最小实现开始。共用抽象应由多个实际用例验证后再提取。

## 授权与持久化候选

| 候选 | 要验证的目标 |
| --- | --- |
| `AuthorizationRequest`、`AuthorizationGrant`、`AuthorizationGrantEvaluator`、`AuthorizationService`、`ResourceRef`、`ScopeDecision` | 分开表达操作人、动作、资源、可信归属与允许授权。验证实际资源用例后再决定是否共用类型，以及字段和方法签名。 |
| `AuthorizedQuerySpec`、`QueryScope`、Mapper 查询方法、参数化 `WHERE` 或 `EXISTS` | 把数据范围送入数据库查询。可先在实际领域用例内实现，再根据复杂查询与复用情况选择表示。 |
| 账号角色、角色权限、角色资源授权关系 | 原 06 与 09 的表名、列和索引是示例。角色共享场次、从组织继承和个人例外等关系应随需求建模。 |
| Spring Security 方法鉴权、MyBatis/MyBatis-Plus 与租户拦截器、Flyway、Testcontainers | 方法鉴权、查询与迁移、数据库测试的已有候选。采用租户拦截器时需单独验证手写查询及非数据库访问路径。 |
| RS256/JWKS、短期访问令牌与刷新会话 | 可评估的验签与会话管理方式。具体认证契约与撤权时效见[待确认事项](11-现有前端OpenAPI契约差异与冻结项.md)。 |

对应约束见 [安全与授权](03-权限数据范围组织租户审批.md)及[工程与编码](02-工程与编码规范.md)。

## 未来能力的候选设计

- 组织可从直接角色演进到组织成员、负责人和角色继承。原 10 的组织表结构、`OrgMembershipResolver` 与查询适配方式留作参考。
- 审批可以采用版本化草稿、审批实例、任务和办理记录。Flowable 和可靠事件回调是候选，选用前先验证实际审批复杂度及重试场景。对已发布内容接入版本审批时，评估存储与读模型迁移。
- 租户部署可评估每客户独立部署、共享应用与共享表、共享应用与独立数据库。分别核对发布运维、全链路隔离、租户数据源和迁移成本。是否采用全局账号也随租户模型决定。
- 旧工程的 Dubbo 可在产生真实内部调用时作为适配候选。事件、缓存、文件存储及消息中间件随实际业务需求评估。
