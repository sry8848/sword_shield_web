# 07 开源实践对照与选型边界

> 以下是架构参考，不表示已把对应开源项目的源码复制到此包中，也不声称本骨架覆盖其全部能力。源码级导入/二次开发应单独校验版本、许可证和适配范围。

## 实际参考对象

1. RuoYi-Vue-Plus：成熟的用户、部门、岗位、菜单、角色及按组织机构划分数据范围；适合作为管理后台的配置体验参考。官方：<https://github.com/dromara/RuoYi-Vue-Plus>、<https://github.com/dromara/plus-doc>。
2. RuoYi-Vue-Pro（芋道）：企业后台的系统管理、多租户和工作流模块组织方式值得研究。<https://github.com/YunaiV/ruoyi-vue-pro>。
3. ABP：组织成员、组织角色、权限、租户数据隔离的解耦思路，**仅作跨技术栈设计参考**，不引入 .NET。<https://abp.io/docs/latest/>。
4. Spring Security：`@EnableMethodSecurity` + `@PreAuthorize` 保护业务操作；<https://docs.spring.io/spring-security/reference/servlet/authorization/method-security.html>。
5. MyBatis-Plus：`TenantLineInnerInterceptor` 是共享表租户 SQL 条件的成熟实现之一。插件不能替代所有自定义 JDBC、缓存、文件和消息隔离。<https://baomidou.com/plugins/tenant/>。
6. AWS SaaS Lens：Silo（独立部署）和 Pool（共享资源）是不同成熟部署模式，后续产品选择不能只由技术兴趣决定。<https://docs.aws.amazon.com/wellarchitected/latest/saas-lens/saas-lens.html>。

## 本项目选择和明确不选择

| 参考 | 采纳 | 暂不采纳 |
|---|---|---|
| 若依 | 稳定权限码、按角色配置范围、菜单按钮授权体验 | 直接把单一部门数据范围列复制给所有业务资源 |
| ABP | 组织成员/组织角色可继承、租户与组织分离 | 直接引入 ABP 框架或照搬全套表 |
| Spring Security | 服务端细粒度权限校验 | 仅网关鉴权或仅前端按钮控制 |
| MyBatis-Plus | 未来正式业务使用 Mapper 与租户拦截 | 在本包示范骨架尚未验证时宣称多租户隔离 |
| AWS SaaS | 独立部署与共享式多租户都留作产品路线 | 把 `tenant_id` 一列当成 SaaS 完成 |

## 为什么没有直接整体二开若依？

旧工程已有独立的 Gateway、用户、活动、内容、文件和 Admin 模块。若直接将一套完整后台框架合并，容易引入另一套账号、认证、API 响应、菜单和数据库命名系统，造成“双权威来源”。当前优先保持已有对外 OpenAPI 契约、领域数据归属，并将若依权限模块作为下一步逐类源码对照/可复用适配的候选，而不是未经验证地强行混合。
