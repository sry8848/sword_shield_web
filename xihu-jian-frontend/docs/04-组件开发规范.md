# 04 组件开发规范

## 1. 组件分类
| 类型 | 位置 | 示例 |
|---|---|---|
| 基础展示组件 | `components/` | `StatusTag`、`PageHeader` |
| 业务组件 | 业务模块目录 | `ActivityCard`、`RegistrationPanel` |
| 页面组件 | `pages/` | `ActivityDetailPage` |
| 布局组件 | `layouts/` | `PortalLayout`、`AdminLayout` |
| 组合式逻辑 | `composables/` | `useActivityList` |

不要把所有组件都放进一个全局目录。只在一个业务模块使用的组件优先就近放置。

## 2. 组件职责
组件主要职责分为展示、输入、业务组合和页面。一个组件不应同时承担 API 请求、全局权限判断、复杂数据转换和大段 UI 展示。

## 3. Props / Emits
Props 只读；Emits 使用明确事件名；复杂表单使用明确表单数据类型；不要把整个 Pinia Store 作为 prop 传给子组件。

## 4. 复用判断
适合抽取：两个以上页面真实复用、交互和展示规则稳定、抽取后调用方式更简单。不应急于抽取：只有一处使用、业务行为不同、需要大量配置才能适配。

## 5. Element Plus
后台表格、表单、分页、弹窗优先使用 Element Plus；优先使用公开 Props / Slots / Events；不依赖内部 DOM 类名实现核心业务；二次封装保持薄，不重复实现组件库已有能力。
