# 04 组件开发规范

## 1. 页面、组件与 Composable

| 单元 | 职责 | 位置 |
|---|---|---|
| 页面 | 组织页面流程、连接路由和查询、组合组件 | 所属 Feature |
| 业务组件 | 负责相对独立的业务展示、输入或交互 | 所属 Feature |
| 基础组件 | 提供应用内跨 Feature 复用的通用展示或交互 | 应用 `components/` |
| 布局组件 | 组织导航、页框和内容区 | 应用 `layouts/` |
| Composable | 提取有状态逻辑或确有复用价值的组合式逻辑 | 优先就近放在所属 Feature |

## 2. 拆分判断

- **MUST** 页面负责流程编排，组件对外声明 Props 和 Emits。请求实现遵循 [06 API 分层](06-接口与数据规范.md#14-前端-api-分层与请求封装)。
- **SHOULD** 简单页面可以直接处理局部状态、查询和交互。业务复杂、逻辑需要复用或值得独立测试时，再提取组件或 Composable。
- **SHOULD** 纯函数和纯业务规则保持为函数。目录按 [02 工程结构规范](02-工程结构规范.md)随实际职责增长。

## 3. Props / Emits
Props 只读；Emits 使用明确事件名；复杂表单使用明确表单数据类型；不要把整个 Pinia Store 作为 prop 传给子组件。

## 4. 组件复用

有真实使用方、交互语义稳定且调用更简单时，优先复用组件。只有一处使用但职责独立的组件可以保留在所属 Feature。

## 5. Element Plus
后台表格、表单、分页、弹窗优先使用 Element Plus；优先使用公开 Props / Slots / Events；不依赖内部 DOM 类名实现核心业务；二次封装保持薄，不重复实现组件库已有能力。
