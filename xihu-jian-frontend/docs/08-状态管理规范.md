# 08 状态管理规范

## 1. 状态分工

| 状态 | 技术 | 示例 |
|---|---|---|
| 组件临时状态 | Vue `ref` / `reactive` | 弹窗、表单草稿 |
| 全局客户端状态 | Pinia | 当前认证会话、应用级偏好 |
| 可分享的筛选、分页等 | Vue Router URL Query | 已提交的关键词、排序和页码 |
| 服务端数据 | TanStack Query | 活动详情、报名列表 |

**SHOULD** 派生值用 `computed` 从现有状态计算。资源 ID 与 URL 状态的规则见 [05 路由与页面查询](05-路由与权限规范.md#8-路由与页面查询)。

## 2. Pinia

**MUST** Pinia 管理全局客户端状态。当前会话的身份和权限可以随会话管理，禁止把服务端查询结果再复制到 Pinia 作为第二份缓存。

**SHOULD** 一个 Store 聚焦明确职责。异步动作有清晰的输入、输出和错误语义，组件负责 DOM 和交互。普通页面状态默认不持久化，密码和验证码等敏感数据不得持久化。认证持久化规则见 [05 Token 约定](05-路由与权限规范.md#5-token)。

## 3. 服务端数据

- **MUST** 使用 TanStack Query 管理查询缓存、请求状态和缓存失效。页面依据查询状态区分加载、成功、空结果和失败，列表与分页总数使用同一次响应。禁止另造全局查询缓存和请求管理框架。
- **MUST** 查询使用稳定的 Query Key，纳入影响结果的资源 ID、有效筛选、排序和分页等参数。私有查询按身份或会话隔离。查询函数使用该次查询对应的参数。
- **MUST** 页面只消费当前条件和当前会话的查询结果。条件变化或离开页面导致旧查询不再有效时，按查询生命周期处理取消，信号传递见 [06 请求封装](06-接口与数据规范.md#14-前端-api-分层与请求封装)。旧响应不得覆盖新数据、总数、加载或错误状态。主动取消不提示为业务失败。
- **MUST** 写操作成功后，按业务关系失效受影响的查询，刷新当前使用的相关数据。失效范围根据写操作影响的实体、列表或汇总确定。
- **MUST** 退出、会话失效或切换账号时，取消旧会话在途的私有查询并清除其缓存，确保晚到结果无法写入新会话。新账号的私有查询在新身份和权限确认后启用。
