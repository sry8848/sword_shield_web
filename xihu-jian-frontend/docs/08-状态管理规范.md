# 08 状态管理规范

## 1. 状态分层
| 状态类型 | 放置位置 | 示例 |
|---|---|---|
| 组件局部状态 | ref / reactive | 弹窗开关、输入框 |
| 页面派生状态 | computed | 筛选结果、按钮是否可用 |
| 跨页面共享状态 | Pinia | 当前用户、认证信息 |
| 服务端数据 | API 请求结果 / 页面缓存 | 活动详情、报名列表 |
| URL 状态 | 路由参数和 query | 活动 ID、筛选条件、分页 |

不要把所有数据都放入 Pinia。

## 2. Pinia 原则
适合放当前登录用户、认证状态、全局偏好和多个页面确实共享的状态。不默认放表格数据、弹窗开关、一次性表单草稿和单组件临时值。

## 3. 服务端数据

- 页面读取服务端数据时，必须统一管理当前查询的 `data`、`loading` 和 `error`，并区分加载、成功、空结果和失败。分页总数与列表数据必须来自同一次有效响应。
- 每次读取必须绑定发起时的查询条件。新查询开始、路由查询对象变化或组件卸载时，必须让不再有效的请求失效。可用请求编号或 watcher 清理标记阻止过期结果写入；请求层支持时可取消旧请求。
- 只有当前有效的请求可以写入数据、总数和错误，或结束加载状态。成功、失败和 `finally` 都必须遵守这条规则。主动取消及过期失败不得触发页面错误提示，当前请求失败时必须展示错误状态。
- 由路由驱动的详情和列表按 [05 的路由与页面查询规则](05-路由与权限规范.md#8-路由与页面查询) 读取。现有演示页面可用 Vue 原生能力管理请求；正式模块出现重复的查询逻辑时，可收敛到轻量 composable。出现共享缓存、跨页面失效等实际需求后再评估 TanStack Query。

## 4. Store 设计
一个 Store 对应明确领域；不操作页面 DOM；异步动作有明确输入输出；错误不能静默吞掉；优先保存业务数据而非整个响应对象。

## 5. 持久化
当前演示 access token 放 sessionStorage；普通页面状态默认不持久化；不持久化密码、验证码和支付敏感信息。生产认证由后端安全设计决定。浏览器存储不是安全边界。
