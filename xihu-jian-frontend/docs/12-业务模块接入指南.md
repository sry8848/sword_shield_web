# 12 业务模块接入指南

## 1. 接入顺序

1. 明确已批准的业务范围、用户场景和验收标准，确定所属应用与 Feature。按 [02 工程结构规范](02-工程结构规范.md)复用已有模块。
2. 确认 OpenAPI。契约有变更时先评审并重新生成类型，按 [06 接口与数据规范](06-接口与数据规范.md)编写业务 API。需要时补充契约一致的 Mock。
3. 在所属 Feature 实现页面和交互，注册懒加载路由及访问条件。按 [04 组件开发规范](04-组件开发规范.md)决定是否抽取组件和 Composable。
4. 从路由取得资源 ID 和可分享的查询条件，按 [08 状态管理规范](08-状态管理规范.md)接入查询、提交和写后刷新。界面覆盖加载、空结果、错误和权限不足。
5. 前后端联调，执行 [09 的质量门禁和适用必测场景](09-测试与质量规范.md)，同步经确认需要调整的文档。

## 2. Definition of Done

- [ ] 实现覆盖已批准的场景和验收标准，依赖符合应用与 Feature 边界。
- [ ] 接口契约已评审，生成类型、业务 API 和适用的 Mock 与契约一致。
- [ ] 页面交互、查询状态、认证和权限边界已经验证。
- [ ] 改动涉及的关键规则及用户流程已有可重复的测试。
- [ ] 质量门禁和联调通过，相关文档已按变更同步。
