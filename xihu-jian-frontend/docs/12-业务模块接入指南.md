# 12 业务模块接入指南

## 1. 接入顺序
1. 明确用户场景和验收标准。
2. 确认 OpenAPI 接口。
3. 定义领域类型和请求 DTO。
4. 在 shared API 工厂中增加接口方法。
5. 在 Mock 中增加相同契约的处理器。
6. 在应用页面中实现交互。
7. 补充权限、空态、错误态和测试。
8. 前后端联调并更新文档。

## 2. 新增 API
在 `packages/shared/src/api/createApi.ts` 中按业务领域增加方法。不要在页面拼接 URL。新增字段时同步更新 TypeScript、OpenAPI、Mock、页面和测试。

## 3. 新增页面
在应用 `src/pages/` 下创建页面；路由懒加载；页面通过 API 模块加载数据；处理 loading、empty、error；登录和权限要求写入 route meta。

## 4. 新增组件
先判断是基础组件、业务组件还是页面组件。只在一个业务模块使用时就近放置；跨多个模块复用且语义稳定后再提升为公共组件。

## 5. 新增 Store
只有跨页面共享状态才进入 Pinia。页面筛选、弹窗开关和临时表单不默认进入 Store。

## 6. 新增 Mock
Mock 与真实接口拥有相同 URL、HTTP 方法、参数、响应、错误码和业务状态。禁止页面出现 mock/real 分支。

## 7. Definition of Done
- [ ] 需求和验收标准明确。
- [ ] 接口契约已评审。
- [ ] 类型定义完整。
- [ ] 页面和交互可用。
- [ ] Loading / Empty / Error 已处理。
- [ ] 权限边界已确认。
- [ ] Mock 与真实接口结构一致。
- [ ] 类型检查和 Lint 通过。
- [ ] 关键业务逻辑有测试。
- [ ] 前后端联调通过。
- [ ] 文档已更新。
