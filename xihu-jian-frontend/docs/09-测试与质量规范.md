# 09 测试与质量规范

## 1. 测试分层
| 层级 | 工具 | 验证内容 |
|---|---|---|
| 静态检查 | TypeScript / ESLint | 类型和代码规范 |
| 单元测试 | Vitest | 工具函数、状态映射、纯函数 |
| 组件测试 | Vitest + Vue Test Utils | Props、事件和交互 |
| E2E | Playwright | 用户关键流程 |
| 接口验证 | OpenAPI / Apifox | 契约有效性、请求响应和错误场景 |

## 2. MVP 必测流程
1. 游客打开首页和活动列表。
2. 游客查看活动详情。
3. 未登录用户报名时进入登录流程。
4. 登录后提交报名。
5. 用户查询报名和凭证。
6. 运营人员创建并发布活动。
7. 运营人员查看报名列表。
8. 核验员核验有效凭证。
9. 重复核验被拒绝。
10. 报名和到场统计口径正确。

## 3. 页面状态覆盖
检查正常数据、空数据、请求失败、加载中、无权限、重复提交、非法输入和窄屏布局。

## 4. 合并前检查
```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```
**MUST** 合并门禁在 GitHub Actions 自动运行 Lint、Typecheck、Test、Build，按 [11 的安装规范](11-开发与部署规范.md#1-本地环境)冻结安装。流水线还必须运行 OpenAPI lint，并用相同契约重新生成类型，检查生成结果与提交产物一致。

**MUST** 依赖边界检查覆盖 Shared 反向依赖应用、两应用互相依赖、绕过 Shared 公共导出和跨 Feature 引用内部实现。边界定义见 [02 工程结构规范](02-工程结构规范.md#3-共享包与依赖边界)。

**MUST** 涉及关键用户流程的改动执行 `pnpm test:e2e`。上述 Lint、Typecheck、Test、Build 和 E2E 命令已提供，其他检查的接入状态见 [14 的骨架整改项](14-待确认事项.md#前端骨架后续整改)。

## 5. 测试数据
测试数据可重复生成；不依赖生产数据；不提交真实个人信息；Mock 覆盖关键状态而不只是成功状态。

## 6. 查询与大会时间必测场景

以下场景按改动涉及的行为纳入测试。

- 用未缓存的条件快速搜索或翻页，主动控制两个请求的完成顺序。旧请求先结束时，当前请求仍显示加载中；新请求先结束时，旧请求随后成功或失败都不得覆盖新数据、总数或错误状态。当前请求失败时应显示错误。
- 在同一详情路由上切换两个活动 ID，验证新 ID 触发加载，旧详情及操作入口清除。旧请求稍后完成时不得影响新详情；新请求失败时不得恢复旧详情。离开页面后让在途请求完成，验证其不会更新页面状态或显示错误提示。
- 对正式筛选分页列表，验证提交新筛选后页码重置，刷新和前进后退能恢复筛选、排序和分页，并且每次有效查询变化只触发一次加载。
- 写操作成功后验证相关详情、列表或汇总失效并刷新，验证无关查询保持原有缓存。
- 分别在 `Asia/Shanghai` 和海外浏览器时区下验证同一时刻的展示。用 `2027-05-20T09:00:00+08:00` 和等价的 `2027-05-20T01:00:00Z` 验证均显示大会当地时间 09:00。涉及正式业务表单时，验证在两个浏览器时区录入同一大会当地时间后，提交值表示同一时刻。

## 7. 认证与关键业务规则必测场景

- 涉及认证时，验证会话恢复、未登录跳转、站内回跳和权限不足。并发过期请求共用一次刷新，原请求最多重试一次。验证刷新失败、普通 401 与 403 的处理差异。
- 涉及会话退出或切换时，验证旧身份和权限清理、私有查询取消和缓存清除。延迟完成旧会话的刷新或查询，验证新会话数据与权限不受影响。
- 涉及关键业务时，用 Vitest 验证可独立执行的纯规则、状态映射和失败分支，用 Playwright 验证受影响的 [MVP 必测流程](#2-mvp-必测流程)。覆盖业务冲突，例如重复报名和重复核验。
