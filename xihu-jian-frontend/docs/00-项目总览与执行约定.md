# 00 项目总览与执行约定

## 1. 项目目标
建立西湖论剑大会门户的统一前端工程底座，支持大会前台与运营后台独立开发、独立构建，同时共享 API 契约、领域类型和基础请求能力。

## 2. 适用范围
- 大会前台：游客浏览、参会用户报名和查询个人报名。
- 运营后台：活动维护、报名管理、现场核验和基础统计。
- 共享基础设施：请求、API 类型、错误处理、Mock。
- 团队协作：编码、测试、接口、AI Coding 和交付约定。

## 3. 规范等级
| 等级 | 含义 | 处理方式 |
|---|---|---|
| MUST | 强制规则 | 代码审查和自动化检查必须阻止违反 |
| SHOULD | 强烈建议 | 有明确理由时可以例外，并记录原因 |
| MAY | 可选做法 | 根据模块复杂度决定是否采用 |

## 4. 核心原则
1. 先业务闭环，再扩展页面数量。
2. 页面不直接访问 Axios；统一通过 API 模块访问后端。
3. 前后端以 OpenAPI / 接口文档约定数据结构。
4. 前台和后台是两个应用，不强行共用页面布局。
5. 共享代码必须具有明确复用价值；不要为了复用而抽象。
6. 业务状态由接口契约定义，前端只负责展示和交互。
7. 前端权限控制改善体验，后端权限校验才是安全边界。
8. Mock 必须模拟真实接口形状，不得成为另一套私有数据协议。
9. 关键业务流程必须有可重复的验收步骤。
10. AI 生成代码必须遵守同一套规范，并经过类型检查、Lint 和测试。

## 5. 当前 MVP 骨架范围
前台：首页、活动列表、活动详情、登录、我的报名。后台：登录、运营概览、活动管理、报名管理、现场核验、基础统计。后续业务模块按 `docs/12-业务模块接入指南.md` 接入。

## 6. 不在当前骨架承诺范围内
真实身份认证、Refresh Token、复杂 RBAC、数据权限、支付、退款、文件服务、直播、消息通知、完整 170 项功能和生产部署均需结合后端与验收要求另行实施。

## 7. 变更规范
涉及工程组织、共享包边界、API 响应格式、错误码、认证方式、角色权限、设计 Token 或部署流程的变更，应先讨论并更新文档。小范围页面实现不需要每次新增架构文档。
