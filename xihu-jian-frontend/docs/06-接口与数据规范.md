# 06 接口与数据规范

## 1. 契约优先
前后端开发前先确定接口契约。推荐使用 OpenAPI 描述，并在 Apifox 中评审、Mock 和调试。本仓库 `openapi/openapi.yaml` 是 MVP 建议草案。接入现有 Spring Boot / Gateway 前必须核对真实后端的 URL、方法、DTO、响应包装、错误码、分页、认证权限和时间格式。

## 2. URL 与 HTTP 方法
- 资源使用名词复数，如 `/api/activities`。
- GET 查询资源，不产生业务副作用。
- POST 创建资源或执行明确业务动作。
- PUT 整体更新，PATCH 局部更新，DELETE 删除。
- 路径参数表达资源标识，查询参数表达筛选和分页。
- 不在 URL 放密码、Token、手机号等敏感信息。

## 3. 请求参数
分页建议 `page`、`pageSize`；时间使用 ISO 8601 并明确时区；金额使用最小货币单位整数或 Decimal 字符串；ID 使用字符串；文件上传使用 multipart/form-data。

## 4. 响应包装（建议契约）
```ts
interface ApiEnvelope<T> {
  code: string
  message: string
  data: T
  traceId?: string
}
```
成功码建议 `SUCCESS`。若现有后端采用 `code/msg/data` 或其他包装，以实际后端为准，统一调整共享请求层，不要在每个页面单独兼容。

## 5. 分页结构（建议契约）
```ts
interface PageResult<T> {
  records: T[]
  total: number
  page: number
  pageSize: number
}
```
若后端返回 rows/total，在 API 适配层转换。

## 6. 错误分类
| 类型 | 处理 |
|---|---|
| 网络错误 | 提示网络不可用，允许重试 |
| 401 | 清理登录态并进入登录流程 |
| 403 | 展示无权限，不自动循环重试 |
| 404 | 展示资源不存在 |
| 409 | 展示业务冲突，例如重复报名 |
| 422 | 展示字段或业务校验错误 |
| 5xx | 展示服务暂不可用，保留 traceId |

错误提示不能泄漏堆栈、SQL、内部服务地址或敏感字段。

## 7. API 分层
页面 -> 应用 API 客户端 -> shared API 工厂 -> Axios 客户端 -> Gateway。页面不得直接调用 Axios。API 方法按业务资源组织，不按页面组织。

## 8. Mock
Mock 路径、方法、参数和响应必须与 OpenAPI 一致；覆盖成功、空数据、业务失败和边界状态；页面不得出现 mock/real 特殊分支；切换由基础设施层完成。

## 9. 幂等
前端可在提交期间禁用按钮，但报名、核验、支付等关键动作必须由后端实现幂等或重复请求保护。前端防抖不能代替后端业务约束。
