# 01 技术选型与架构设计

## 1. 技术基线
| 层次 | 选型 | 责任 |
|---|---|---|
| UI 框架 | Vue 3 | 视图与组件 |
| 语言 | TypeScript | 静态类型约束 |
| 构建 | Vite | 开发服务器和生产构建 |
| UI 组件 | Element Plus | 后台表格、表单、弹窗等基础控件 |
| 路由 | Vue Router 4 | 页面导航和路由元数据 |
| 状态管理 | Vue 响应式状态、Pinia、Vue Router、TanStack Query | 职责见 [08 状态管理规范](08-状态管理规范.md) |
| HTTP | Axios | HTTP 请求 |
| API 契约 | OpenAPI 3.1、`openapi-typescript` | 接口 DTO 契约与 TypeScript 类型生成 |
| API 协作 | Apifox | 接口评审、Mock、调试 |
| 代码检查 | ESLint + antfu preset | 统一静态检查 |
| 单元测试 | Vitest + Vue Test Utils | 工具和组件测试 |
| E2E | Playwright | 用户关键流程验证 |

## 2. 为什么采用 Monorepo
仓库包含 `apps/portal` 和 `apps/admin` 两个独立应用，以及 `packages/shared` 共享包。两个应用独立开发、构建和部署，共享契约类型和请求基础设施。

## 3. 依赖方向
允许：`portal -> shared`、`admin -> shared`。禁止 shared 依赖任何 app，禁止 portal 和 admin 相互依赖。共享包不得放页面、布局、应用专属路由或只在单个应用使用的组件。

## 4. 应用边界
- Portal：面向游客和参会者，重内容阅读、活动发现和移动端体验。
- Admin：面向工作人员，重数据检索、表单录入、批量处理和权限边界。
- Shared 只提供真正跨应用复用的基础设施、公共契约类型和通用工具。业务能力默认归属应用。

## 5. 业务组织
两个应用均采用轻量 Feature-based Architecture。按业务领域就近组织页面、组件、查询和 API，按实际复杂度拆分。依赖规则和目录见 [02 工程结构规范](02-工程结构规范.md)，拆分判断见 [04 组件开发规范](04-组件开发规范.md)。
