# 01 技术选型与架构设计

## 1. 技术基线
| 层次 | 选型 | 责任 |
|---|---|---|
| UI 框架 | Vue 3 | 视图与组件 |
| 语言 | TypeScript | 静态类型约束 |
| 构建 | Vite | 开发服务器和生产构建 |
| UI 组件 | Element Plus | 后台表格、表单、弹窗等基础控件 |
| 路由 | Vue Router 4 | 页面导航和路由元数据 |
| 状态管理 | Pinia | 跨页面共享状态 |
| HTTP | Axios | HTTP 请求 |
| API 契约 | OpenAPI 3.1 草案 | 前后端接口约定 |
| API 协作 | Apifox | 接口评审、Mock、调试 |
| 代码检查 | ESLint + antfu preset | 统一静态检查 |
| 单元测试 | Vitest + Vue Test Utils | 工具和组件测试 |
| E2E | Playwright | 用户关键流程验证 |

## 2. 为什么采用 Monorepo
仓库包含 `apps/portal` 和 `apps/admin` 两个独立应用，以及 `packages/shared` 共享包。两个应用独立启动、独立构建；共享 API 类型和请求基础设施。当前不引入复杂构建编排工具，pnpm workspace 已足够。

## 3. 依赖方向
允许：`portal -> shared`、`admin -> shared`。禁止 shared 依赖任何 app，禁止 portal 和 admin 相互依赖。共享包不得放页面、布局、应用专属路由或只在单个应用使用的组件。

## 4. 应用边界
- Portal：面向游客和参会者，重内容阅读、活动发现和移动端体验。
- Admin：面向工作人员，重数据检索、表单录入、批量处理和权限边界。
- Shared：只放跨应用且稳定的 API、类型、HTTP、Mock 和通用工具。

## 5. 为什么不直接复制后台模板
vue-pure-admin、Vben Admin 适合研究和借鉴，但包含自身产品假设、菜单体系、权限实现和 UI 方案。本项目只吸收经过评估的基础设计，不把模板全部抽象带入。

## 6. 环境约定
Node.js >= 22.12；pnpm workspace；Portal 5173；Admin 5174；开发 API 默认 `/api`；Vite 代理默认 `http://localhost:8080`；Mock 默认开启。

## 7. 关键决策
| 决策 | 当前方案 | 重新评估触发条件 |
|---|---|---|
| 多应用组织 | pnpm workspace Monorepo | 团队部署、权限或仓库治理要求变化 |
| UI | Element Plus | 前台需要独立设计系统时 |
| API | 共享 API 工厂 | 后端契约或网关协议变化 |
| Mock | Axios Mock Adapter | 需要浏览器级拦截或跨应用共享状态时 |
| 状态管理 | Pinia + 局部响应式状态 | 出现复杂跨页面状态流时 |
