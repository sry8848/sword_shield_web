# 11 开发与部署规范

## 1. 本地环境
Node.js `>=22.12.0`，使用根 `package.json` 声明的 pnpm 10.x。Windows 可使用 fnm / nvm-windows 统一 Node 版本。Portal 和 Admin 默认端口分别为 5173 和 5174。

**MUST** 在前端 Workspace 提交 `pnpm-lock.yaml`。锁文件入库后，日常开发和 CI 均使用 `pnpm install --frozen-lockfile`。经批准变更依赖时，同步更新清单和锁文件。当前锁文件的落地状态见 [14 的骨架整改项](14-待确认事项.md#前端骨架后续整改)。

## 2. 环境变量
每个应用分别维护 `.env.development` 和 `.env.production.example`，本地私有配置使用 `.env.*.local`。`VITE_` 前缀变量会暴露给浏览器，禁止存放数据库密码、服务端 Secret 和私钥。

## 3. 开发代理
本地默认 `/api` 代理至 `http://localhost:8080`，应按真实 Gateway 端口调整。生产建议由 Nginx、Gateway 或同域反向代理处理 API 路由。

## 4. 构建产物
**MUST** Portal 和 Admin 独立开发、构建和部署。应用分别输出 `dist/`，可分别运行 `pnpm --filter @xhlj/portal build` 和 `pnpm --filter @xhlj/admin build`。合并前按 [09 质量门禁](09-测试与质量规范.md#4-合并前检查)验证两个应用。

部署时分别配置静态资源缓存和 API 反向代理。HTML 入口不应长期强缓存，带 hash 静态资源可长期缓存。

## 5. Git 分支
建议 `main`、`feature/<module>-<topic>`、`fix/<module>-<topic>`、`docs/<topic>`。提交信息采用 Conventional Commits，例如 `feat(portal): add activity detail`、`fix(admin): prevent duplicate check-in`。

## 6. Pull Request
包含背景目标、修改范围、UI 截图、API/数据结构变化、测试命令和结果、风险与回滚方式。

## 7. 发布检查
**MUST** 发布时关闭 Mock，检查 API 地址、History fallback、CORS、Cookie 和 Gateway 配置，验证核心流程和浏览器网络请求，确认无敏感信息进入构建产物。认证部署按 [06 认证约定](06-接口与数据规范.md#81-认证约定)执行。
