# 07 UI 设计规范

## 1. 两套布局
大会前台：蓝白视觉基调、顶部全局导航、内容留白充足；首页可有主题视觉区，内页不重复使用首页式大 Banner；内页直接进入正文，不默认增加面包屑或独立页面标题区；移动端优先保留标题、时间、地点、状态和主操作。

运营后台：左侧菜单 + 顶部工具栏 + 内容区；页面标题和操作区清晰；表格、筛选、分页、表单布局统一；危险操作二次确认；关键状态不能只依赖颜色表达。

## 2. 设计 Token
| Token | 用途 |
|---|---|
| `--color-primary` | 主品牌蓝 |
| `--color-text` | 正文 |
| `--color-muted` | 次要文字 |
| `--color-border` | 边框 |
| `--color-surface` | 卡片背景 |
| `--radius-md` | 常规圆角 |
| `--shadow-card` | 卡片阴影 |
| `--content-width` | 内容最大宽度 |

新增颜色、间距和圆角时优先扩展 Token，不在页面散落硬编码。

## 3. 字体与间距
正文优先系统中文字体栈；标题、正文、辅助信息层级清楚。使用 4px 基础间距节奏：4、8、12、16、24、32、40、48。

## 4. 页面状态
异步页面至少考虑 Loading、Success、Empty、Error。表单考虑初始、校验失败、提交中、成功和失败。

## 5. 响应式
建议断点：Mobile < 768px；Tablet 768–1199px；Desktop >= 1200px。断点需通过实际页面验证，不能只缩小桌面布局。

## 6. 可访问性
交互元素支持键盘操作；输入框有 label；图片有 alt；状态不只用颜色表达；弹窗焦点行为合理；移动端点击目标尺寸足够。

## 7. Element Plus
后台优先复用 Element Plus。前台可组合 Element Plus 或自有轻量组件，但没有明确理由不要引入第二套完整 UI 库。
