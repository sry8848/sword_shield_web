# 10 AI Coding 协作规范

## 1. 目标
让 AI 在既有工程边界内完成任务，避免每次生成代码都引入新架构、重复组件或不一致数据结构。

## 2. 接任务前必须确认
目标用户和业务场景、任务所属 Portal/Admin/Shared、现有实现位置、接口是否定义、是否影响路由权限类型组件、验收标准。信息不足且会改变实现方向时先提问，不得编造业务规则。

## 3. 修改前检查
AI 必须阅读 README、相关规范、目标模块相邻代码、API 类型和 Mock、相关测试。不得只根据一句话重建目录或替换基础设施。

## 4. 修改边界
MUST：不随意升级依赖主版本；不擅自引入新 UI / 状态 / 请求库；页面不直接写 Axios；不复制已有公共组件；API 契约变化同步更新 OpenAPI、类型和 Mock；权限不能只隐藏按钮；不把真实密钥写入前端；不删除无关业务代码。

SHOULD：优先局部改动；复杂任务先给实施计划；新增依赖说明必要性；关键逻辑增加测试；不确定行为标注待确认。

## 5. AI 交付内容
说明修改文件、业务变化、接口和类型变化、验证方式、未完成事项、风险和后端配合项。无法运行验证时必须明确说明，不得声称通过。

## 6. 提示词模板
```text
请先阅读 README 和相关规范，再检查目标模块现有实现。
本次目标：
业务场景：
涉及应用：Portal / Admin / Shared
接口契约：
验收标准：
约束：不改变无关架构；不新增未经说明的依赖；页面不得直接访问 Axios；复用已有类型和组件；同步更新必要测试和文档。
完成后列出修改文件、验证命令、结果和遗留风险。
```
