# 05 路由与权限规范

## 1. 路由组织
Portal 和 Admin 各自维护路由表。name 唯一稳定；path 使用小写 kebab-case；动态参数有业务含义；页面懒加载；meta 声明标题、登录要求和前端角色要求。

## 2. 路由元数据
```ts
interface AppRouteMeta {
  title: string
  requiresAuth?: boolean
  roles?: Array<'USER' | 'ADMIN' | 'OPS' | 'CHECKIN'>
}
```

## 3. 认证与授权边界
认证（Authentication）确认用户是谁；授权（Authorization）确认用户能做什么。前端路由守卫只能控制页面入口和交互展示，不能作为安全边界。后端必须对每个受保护接口进行身份认证和权限校验。

## 4. 登录跳转
访问受保护页面时未登录则跳登录页；登录后回到原目标；redirect 必须限制为站内路径；退出清理用户状态。不要把任意外部 URL 作为 redirect。

## 5. Token
当前 Mock 使用 sessionStorage 保存演示 access token。生产环境应与后端确认 Access Token 生命周期、Refresh Token 是否采用 HttpOnly + Secure + SameSite Cookie、刷新和注销流程、并发 401 处理及 Gateway 透传。不要将长期 Refresh Token 放入 localStorage。

## 6. 角色与数据范围
角色示例：USER、ADMIN、OPS、CHECKIN。真实角色以业务权限矩阵为准。页面级角色不等于数据范围；核验员只能核验授权场次等规则必须由后端强制校验。前端只展示后端提供的可操作范围。

## 7. 菜单
菜单由路由配置或后端授权菜单生成，不维护与路由脱节的第二份硬编码菜单。隐藏菜单不代表接口安全。
