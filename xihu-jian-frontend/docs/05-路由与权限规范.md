# 05 路由与权限规范

## 1. 路由组织
Portal 和 Admin 各自维护路由表。name 唯一稳定；path 使用小写 kebab-case；动态参数有业务含义；页面懒加载；meta 声明标题、登录要求和后台访问条件。

## 2. 路由元数据

**MUST** 受保护的路由用 `requiresAuth` 表达登录要求。后台路由根据后端授权信息声明访问条件，权限码见 [06 RBAC 基础权限约定](06-接口与数据规范.md#12-rbac-基础权限约定)。

## 3. 认证与授权边界
认证（Authentication）确认用户是谁；授权（Authorization）确认用户能做什么。前端路由守卫只能控制页面入口和交互展示，不能作为安全边界。后端必须对每个受保护接口进行身份认证和权限校验。

## 4. 登录跳转
**MUST** 进入受保护路由前先完成会话恢复和所需权限的读取，再判断是否放行。未登录时跳转到登录页，登录后回到已验证的站内目标。已登录但权限不足时进入可访问页面或显示无权限。

**MUST** 登录成功或恢复会话后建立当前身份与权限。会话失效、退出或切换账号时，清理旧身份与权限，并按 [08 服务端数据规则](08-状态管理规范.md#3-服务端数据)处理私有查询。旧会话的在途请求不得更新新会话状态。

## 5. Token
当前 Mock 使用 `sessionStorage` 保存演示 Access Token。生产认证按 [06 的 Token 约定](06-接口与数据规范.md#81-认证约定) 接入。浏览器管理 Refresh Token Cookie，前端只管理 Access Token 和登录状态。

## 6. 角色与数据范围
首期角色范围以 [D13](14-待确认事项.md#p1影响后台管理和统计口径) 的评审结果为准。数据范围由后端强制校验，前端按后端返回的权限和可操作范围展示。

## 7. 菜单
菜单由路由配置或后端授权菜单生成，不维护与路由脱节的第二份硬编码菜单。隐藏菜单不代表接口安全。

## 8. 路由与页面查询

- **MUST** 详情资源 ID 由路由参数表达。首次进入和 ID 变化时，以当前 ID 更新查询条件。切换期间清除旧详情和对应操作入口。
- **MUST** 可分享的筛选、排序和分页以 URL query 为唯一来源。输入框可以保存未提交的草稿。提交新筛选时一次导航写入筛选条件并将页码重置为 1，翻页只修改分页条件。
- **MUST** 初次进入、刷新及浏览器前进后退时从 URL 恢复查询条件。解析缺省和无效值后，将有效条件传给查询。搜索和翻页事件只更新 URL，由同一查询入口响应条件变化。
- 查询生命周期和写后刷新按 [08 服务端数据规则](08-状态管理规范.md#3-服务端数据)处理。
