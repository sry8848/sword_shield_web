# 05 路由与权限规范

## 1. 路由组织
Portal 和 Admin 各自维护路由表。name 唯一稳定；path 使用小写 kebab-case；动态参数有业务含义；页面懒加载；meta 声明标题、登录要求和前端角色要求。

## 2. 路由元数据
```ts
interface AppRouteMeta {
  title: string
  requiresAuth?: boolean
  roles?: Array<'SUPER_ADMIN' | 'EVENT_OPERATOR' | 'CHECKIN_STAFF' | 'DATA_OPERATOR'>
}
```

## 3. 认证与授权边界
认证（Authentication）确认用户是谁；授权（Authorization）确认用户能做什么。前端路由守卫只能控制页面入口和交互展示，不能作为安全边界。后端必须对每个受保护接口进行身份认证和权限校验。

## 4. 登录跳转
访问受保护页面时未登录则跳登录页；登录后回到原目标；redirect 必须限制为站内路径；退出清理用户状态。不要把任意外部 URL 作为 redirect。

## 5. Token
当前 Mock 使用 `sessionStorage` 保存演示 Access Token。生产认证按 [06 的 Token 约定](06-接口与数据规范.md#81-认证约定) 接入。浏览器管理 Refresh Token Cookie，前端只管理 Access Token 和登录状态。

## 6. 角色与数据范围
普通参会页面用 `requiresAuth` 声明登录要求。后台页面的 `roles` 使用 [06 的 RBAC 角色编码](06-接口与数据规范.md#121-内置角色草案)，首期角色范围以 [D13](14-待确认事项.md#p1影响后台管理和统计口径) 的评审结果为准。核验员只能核验授权场次等数据范围规则由后端强制校验。前端只展示后端提供的可操作范围。

## 7. 菜单
菜单由路由配置或后端授权菜单生成，不维护与路由脱节的第二份硬编码菜单。隐藏菜单不代表接口安全。
