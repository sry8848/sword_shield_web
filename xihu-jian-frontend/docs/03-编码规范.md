# 03 编码规范

## 1. 总体要求
- 使用 TypeScript；Vue 组件使用 `<script setup lang="ts">`。
- 优先 Composition API，开启严格类型检查。
- 禁止使用 `any` 逃避类型问题；无法表达时用 `unknown` 并收窄。
- 不提交未使用变量、调试日志和临时注释代码。

## 2. 命名
组件 PascalCase；变量和函数 camelCase；类型 PascalCase；真正全局常量 UPPER_SNAKE_CASE；布尔值优先 `is`、`has`、`can`、`should` 前缀；事件处理函数用 `handle` 前缀。

避免 `data1`、`temp2`、`doIt` 等无业务含义名称。

## 3. Vue 组件
- 单组件聚焦一个明确职责。
- 模板不写复杂业务表达式，派生值使用 computed。
- 可复用逻辑使用 composable。
- Props 和 Emits 声明类型；Props 只读。
- 列表使用稳定业务 ID 作为 key。
- 不把所有逻辑塞进巨型页面组件。

## 4. TypeScript
- API 响应、领域对象、表单输入分别定义类型。
- 不直接把后端响应对象当作表单对象修改。
- 可选字段使用 `?`，可空字段明确写 `| null`。
- ID 使用字符串，避免大整数精度丢失。
- 外部输入视为不可信数据。

## 5. 异步与错误处理
每个异步页面请求考虑 loading、empty、error；用户操作失败给出可理解反馈；不吞异常；提交期间禁用按钮，但报名、核验等仍需后端幂等。

## 6. 样式
优先 scoped 样式；全局样式只放 Reset、字体、设计 Token 和明确的全局覆盖；避免 `!important`；优先 CSS 变量。

## 7. 自动化规则
ESLint 是代码规范执行入口。本工程采用 antfu ESLint preset，不叠加冲突的第二套格式化规则。合并前运行 lint、typecheck、test 和 build。

## 8. 注释
解释“为什么”，而不是重复代码做什么。复杂业务规则、兼容性处理和暂时不能消除的限制必须说明原因。
