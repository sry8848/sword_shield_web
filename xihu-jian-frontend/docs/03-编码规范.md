# 03 编码规范

## 1. 总体要求
- 使用 TypeScript；Vue 组件使用 `<script setup lang="ts">`。
- 优先 Composition API，开启严格类型检查。
- 禁止使用 `any` 逃避类型问题；无法表达时用 `unknown` 并收窄。
- 不提交未使用变量、调试日志和临时注释代码。

## 2. 命名
组件 PascalCase；变量和函数 camelCase；类型 PascalCase；真正全局常量 UPPER_SNAKE_CASE；布尔值优先 `is`、`has`、`can`、`should` 前缀；事件处理函数用 `handle` 前缀。

避免 `data1`、`temp2`、`doIt` 等无业务含义名称。

## 3. Vue 组件
- 单组件聚焦一个明确职责。
- 模板不写复杂业务表达式，派生值使用 computed。
- 页面、组件和 Composable 的拆分标准见 [04 组件开发规范](04-组件开发规范.md)。
- Props 和 Emits 声明类型；Props 只读。
- 列表使用稳定业务 ID 作为 key。

## 4. TypeScript
- 接口 DTO 使用 OpenAPI 生成类型。展示或表单模型确有独立语义时再定义，见 [06 类型规范](06-接口与数据规范.md#53-typescript-类型与生成)。
- 不直接把后端响应对象当作表单对象修改。
- 可选字段使用 `?`，可空字段明确写 `| null`。
- ID 使用字符串，避免大整数精度丢失。
- 外部输入视为不可信数据。

## 5. 异步与错误处理
按 [08 服务端数据规则](08-状态管理规范.md#3-服务端数据)处理查询状态。用户操作失败时给出可理解的反馈并保留错误语义。提交期间禁用按钮，报名、核验等关键动作的幂等要求见 [06 接口与数据规范](06-接口与数据规范.md#16-幂等与重复请求保护)。

## 6. 样式
优先 scoped 样式；全局样式只放 Reset、字体、设计 Token 和明确的全局覆盖；避免 `!important`；优先 CSS 变量。

## 7. 自动化规则
ESLint 是代码规范执行入口。本工程采用 antfu ESLint preset，不叠加冲突的第二套格式化规则。合并门禁见 [09 测试与质量规范](09-测试与质量规范.md#4-合并前检查)。

## 8. 注释
方法和函数的注释说明职责、输入与输出。用带序号的注释说明逻辑块的步骤，并解释核心变量的含义。复杂业务规则、兼容处理和关键取舍的原因用独立注释说明。
