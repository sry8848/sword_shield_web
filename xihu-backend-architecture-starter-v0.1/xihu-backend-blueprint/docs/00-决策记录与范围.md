# 00 架构决策记录与范围

## 一、事实基线与证据等级

- **直接读取当前仓库 `dev` 分支**：根 `pom.xml` 包含 `sword-shield-common/api/gateway/user/activity/content/interaction/file/admin`；Java 17、Spring Boot 3.2.5、Spring Cloud 2023.0.3；旧 README 表示 Gateway + Dubbo、Nacos、MySQL、Redis、RocketMQ、MinIO。不能以该 README 证明每条路径运行正确。
- **基于上传文件/会话副本**：`mvp.md` MVP 为“大会门户 + 普通报名 + 现场核验 + 基础运营”；完整功能清单 170 项；`openapi.yaml` 是前后端唯一机器可读契约；后台角色、数据范围存在尚未实现的缺口。
- **未获证实**：最新 `dev` 是否包含原先前端 `xihu-jian-frontend` 的文档；当前仓库是否已有同名 OpenAPI；数据库产品究竟必须是 SQL Server 还是允许 MySQL。

## 二、架构必须保持的领域事实

1. Conference（届次）包含 Event（可报名场次），一个 Event 可关联多个 Speaker，嘉宾也可参加多个场次。
2. 账号是统一身份；普通报名只属于本人，现场核验必须同时校验凭证和授权场次。
3. 后台是界面入口，不是拥有所有领域表的“万能服务”；Activity 拥有 Event、Registration、Credential、CheckIn 的写入。
4. 数据范围不仅是场次；今后可对用户、资讯、展商、工单、报名等多资源按不同关系过滤。
5. Menu/Button 是权限的 UI 投影；后端权限码为稳定标识，不能依赖隐藏按钮防越权。

## 三、明确 ADR（架构决策记录）

| ID | 决策 | 原因 | 演进边界 |
|---|---|---|---|
| ADR-01 | 保留现有微服务领域分工；新骨架先提供 Gateway + Identity + Activity 的可部署示例 | 与功能清单和既有代码方向一致；避免一次生成空服务矩阵 | Content/File/Interaction 在业务阶段增加，不改变领域数据所有权 |
| ADR-02 | Java 17 + Spring Boot 3.2.5 + Cloud 2023.0.3 作为兼容基线 | 与旧工程对齐 | 稳定性和安全补丁应在正式开发前统一升级，非隐式升级 |
| ADR-03 | 对外 REST + `/api/v1`，保持统一响应和 OpenAPI 优先 | 避免前端重新适配 | Dubbo/RPC 只在确有跨服务调用时按标准引入；第一版不做空 RPC |
| ADR-04 | 数据访问归业务服务持有，禁 Admin 直写 Activity 表 | 避免状态和授权分裂 | 未来可拆数据库/多租户而不改业务所有权 |
| ADR-05 | RBAC 与数据范围分离；按 `resourceType + action` 计算范围 | 可扩展到 User/Article/Exhibitor 等 | 授权来源未来可增加组织、部门、个人、租户上下文 |
| ADR-06 | MVP 只实现需要的范围，但先统一接口与 fail-closed 规则 | 防漏授权 | 复杂查询需业务域提供受控 QueryScope，不使用万能 SQL 字符串拼接 |
| ADR-07 | 重要状态变化使用显式命令方法并审计 | 未来审批不会直接覆写已发布数据 | 引入审批时增加版本化草稿/审批实例，不宣称零重构 |
| ADR-08 | 本包单租户演示保留 tenantId 字段及上下文接口，**未宣布实现多租户** | 用户计划以后做多租户面试能力，但产品定位未定 | 若选择共享数据库，多租户拦截、索引与隔离测试单独迭代；若选择独立部署可不启用租户 |
| ADR-09 | MySQL 为示范库，Flyway 管理迁移；待课程明确是否必须 SQL Server | 与现有旧工程一致 | 不承诺 SQL Server 兼容，必须单独迁移/测试 |
| ADR-10 | 构建骨架不得覆盖旧项目；新工程在独立目录交付 | 旧 `dev` 分支实现与计划差异较大 | 经编译与接口验收后再选择替换/并行迁移 |

## 四、尚待冻结而不阻止架构开工

- 正式使用 MySQL 或 SQL Server；是否允许升级 Spring Boot 版本。
- 登录凭证最终采用 RS256、refresh 会话与权限变更失效方案。
- 多租户最终选择共享实例/独立部署；全局账号加入多个租户是否必要。
- 同一个账户有多个角色时，冲突规则如何处理；本规范默认“允许规则并集，租户隔离绝不可覆盖，显式拒绝优先”。
- 菜单是否开放数据库动态管理；当前固定前端菜单可继续使用稳定权限码。

## 五、交付边界

架构规范可以覆盖完整 170 项的设计原则，但代码骨架不是 170 项实现；也不是对原赛题完成率的声明。后续迭代按 MVP OpenAPI 和验收测试依次实现。
