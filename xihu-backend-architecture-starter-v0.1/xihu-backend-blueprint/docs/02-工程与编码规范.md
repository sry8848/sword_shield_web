# 02 后端工程及编码规范 v0.1

## 1. 技术基线

- Java 17，Maven reactor，多模块；Spring Boot 3.2.5，Spring Cloud 2023.0.3 为现有工程兼容基线。升级须整套依赖兼容验证。
- Spring Security Resource Server 保护管理接口。Demo HS256 仅供本机演示，正式环境建议 RS256/JWKS 与短期 Token + refresh 会话。
- MyBatis-Plus Spring Boot 3 Starter 3.5.9 为骨架持久层示例（适配旧 Boot3 基线），复杂 SQL 可用 XML。正式升级依赖版本时需兼容测试；多租户插件需配套 JSQLParser，不能只加 `tenant_id` 就宣称隔离。
- Flyway 迁移（业务服务各自 schema/migrations）、MySQL 8、Redis/MinIO/RocketMQ 仅按业务需要引入。
- 不为未来功能引入空的 Workflow、Organization、TenantAdmin 运行服务。

## 2. 模块依赖与目录规范

```text
backend/
  common/      无 Spring Web 应用主类；API Envelope、错误模型、纯权限模型
  gateway/     WebFlux 路由，禁止放业务 Repository
  identity-service/
    controller/        HTTP DTO + 校验
    application/       登录、角色授权应用用例
    domain/            账号、身份、权限规则
    infrastructure/    数据库/JWT/缓存实现
  activity-service/
    controller/
    application/       事务边界、业务命令
    domain/            大会/活动/报名/核验规则
    infrastructure/    Mapper、Repository、事件适配器
```

依赖方向：`controller -> application -> domain interface`；`infrastructure implements domain port`。领域不能依赖 Gateway 或别的服务的 Mapper；common 不允许装业务实体。小型类允许在单文件内，防止无意义包装。

## 3. HTTP/API 约定

- 前缀 `/api/v1`；公开 `/public`、登录 `/auth`、用户自己 `/me`、后台 `/admin`。
- DTO `record` 可用于不可变请求；入参 Jakarta Validation 校验。不要直接暴露数据库 PO。
- 业务资源 ID 通过 API 用 string，防 JS 64-bit 精度损失。
- 时间 ISO 8601 带时区，数据库保存 UTC 即时点，显示按 `Asia/Shanghai`；涉及会场本地日期的查询按明确时区转换。
- 分页 `page>=1`, `1<=pageSize<=100`；响应 `{items,pageInfo:{page,pageSize,total,totalPages}}`，排序字段白名单。
- 400 入参格式；401 未认证；403 已认证但无权；404 不存在/隐藏跨租户实体；409 冲突；422 业务不满足；500 不泄露内部实现。
- 统一 envelope 的 `traceId` 与日志 MDC 对应。`openapi.yaml` 是机器可读契约唯一来源，任何接口变更先改契约再实现。

## 4. 鉴权与数据范围

- 权限码 `resource:action`，固定稳定，例如 `event:publish`、`checkin:create`、`user:read`。
- 前端菜单、按钮可以用权限码控制可见，不是安全边界；每个后端管理操作执行同等授权。
- 详情：`check(subject, action, resource)`；列表：按策略构造受限查询；批量更新先按权限选择可操作记录，再在同事务更新。
- ScopePolicy 必须包含 resourceType、action，不可全局只存单一 `data_scope`；当前至少 ALL / SELF / ASSIGNED / NONE。
- 角色可以有多个权限范围；默认拒绝，冲突策略明示；租户隔离不可被 ALL 权限覆盖。
- 资源集合可绑定 role/organization/user，**不要求所有资源存入一张万能资源表**。具体资源归属和关联由领域持有。

## 5. 数据库设计

- 表：`snake_case`；字段：`snake_case`；Java：`camelCase`；主键 BIGINT/UUID 策略统一，外部 API ID 序列化为 string。
- 所有敏感业务表必须具有明确 account/event/conference 归属；若启用共享式多租户，包含 tenant_id 以及租户内索引与组合关系校验。
- 唯一约束保证幂等 (`event_id, account_id`、`registration_id` 及业务幂等键等)；资金和库存必须有事务或原子操作。
- Flyway 迁移只新增版本，不修改已执行的 V 脚本；生产不得 `ddl-auto=update`；种子测试数据不要进生产迁移。
- 禁止跨服务读写别人的表（即使当前连接到同一个 MySQL）。
- 禁止业务表直接存完整 JWT、明文密码、完整凭证 Token；只存不可逆哈希或必要元信息。

## 6. 日志、监控、错误

- MDC `traceId`；结构化日志脱敏；异常代码稳定；业务错误避免直接返回 SQL/类名。
- 关键状态变更记录谁、何时、哪个资源、前后状态和原因（涉及个人隐私的数据不记录全文）。
- 安全事件：跨租户访问尝试、权限拒绝、凭证重复核验需可追溯。

## 7. 配置与部署

- 密钥和密码只能来自环境或密钥系统，不提交真实密钥；dev 默认密码必须显著标注、不可用于公网。
- Compose 提供 MySQL；其他服务可增量引入；每个服务有健康检查和独立端口，避免相互直接读写数据库。
- 发布构建使用固定依赖版本，运行单元/集成测试，发布前对照 OpenAPI 做契约校验。

## 8. 测试分层

- Unit：权限范围、业务状态、计数规则、角色并集/拒绝语义。
- Integration（Testcontainers MySQL）：唯一约束、条件更新、事务回滚、复杂 SQL 数据范围、Flyway。
- Security：所有敏感端点无 Token、无权限、错误租户、错误资源范围；分别验证 401/403/404。
- Contract：生成响应与当前 OpenAPI 比对；Windows `mvn -B clean verify`。

## 9. 特别禁止

- 根据客户端提交的 userId/tenantId 决定本人或租户归属。
- 将全部权限判断放 Gateway，而业务服务不校验。
- 用前端按钮是否显示替代服务端鉴权。
- 在各 Mapper 随机复制数据范围 SQL；设计具名授权查询入口并验证复杂 JOIN。
- 用一张无限多态关系表替代清晰的业务归属。
- 声称“预留接口”意味着未来实现组织、审批、多租户零重构。
