## 3. 复查方法

1. 准备测试专用 MySQL 和 Redis。Identity 启用 `test`，配置 `IDENTITY_TEST_DB_URL`、`IDENTITY_TEST_DB_USERNAME`、`IDENTITY_TEST_DB_PASSWORD` 和外置的 `IDENTITY_PORTAL_PRIVATE_KEY`。Redis 连接使用 Spring Boot 原生的 `SPRING_DATA_REDIS_HOST` 和 `SPRING_DATA_REDIS_PORT`，启用认证时由环境注入 `SPRING_DATA_REDIS_PASSWORD`。测试实例的凭证留在本机环境。[Identity 环境配置与开发库初始化](../../设计/登录设计/Identity环境配置与开发库初始化_2026-11-23_11-02.md)
2. 启动 Identity、Gateway 和 Portal。为核对测试依赖组件，临时为 Identity 设置 `--management.endpoint.health.show-components=always`。为收集成功健康检查的追踪日志，临时将 Gateway 的 `GatewayAccessLog` 和 Identity 的 `DispatcherServlet` 调至 `DEBUG`。
3. 分别请求 `8081/actuator/health`、`8080/api/internal/identity/health` 和 `5173/api/internal/identity/health`。可在第三个请求附带一个有效的 W3C `traceparent`，对照两个服务实际日志里的 `trace.id`。在测试库查询 `flyway_schema_history` 的 `version`、`success`，并用 `identity_account_role` 核对两条种子账号的角色。
4. 对测试实例依次模拟超时、Redis 停止和 Identity 停止。使用第二个 Gateway 实例及独立端口设置 `--spring.cloud.gateway.server.webflux.httpclient.response-timeout=1ns`，以便主 Gateway 继续验证其余故障。

## 4. 自动化测试的覆盖边界

`GatewayIdentityRoutingTest` 使用真实 Gateway 与可控测试上游，验证合法 Problem Details 透传、连接拒绝、连接提前关闭、响应超时及故障日志。包裹的 `UnknownHostException` 在错误处理器层测试，避免测试依赖本地 DNS 对保留域名的处理。入口无追踪头、追踪头非法、线程作用域丢失及请求 Observation 缺失分别有回归用例。
