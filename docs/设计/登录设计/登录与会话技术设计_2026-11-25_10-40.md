# 登录与会话模块技术设计

依据[业务设计 v1.2](登录设计_2026-11-25_10-40.md)和[技术评审](../../需求/登录与会话模块/登录与会话模块技术评审_2026-11-10_19-17.md)。接口以 [OpenAPI](../../../xihu-jian-frontend/openapi/openapi.yaml) 为准。

## 1. 交付范围与服务职责

Portal 和 Admin 共用账号，分别维护独立会话、Cookie、Access Token 受众和前端登录状态。同一账号可同时登录两端和多个设备。本期 Admin 只用 `SUPER_ADMIN` 准入，初始账号沿用[账号基础数据与初始账号需求](../../需求/登录与会话模块/账号基础数据与初始账号需求_2026-11-11_09-01.md)。注册、角色配置、细粒度权限和密码找回由后续模块交付。

- Identity 拥有账号、角色、会话及凭证数据，负责密码校验、登录限流、JWT 签发、JWKS 发布、会话管理、在线安全状态同步和审计。
- Activity 等资源服务独立校验 JWT 的签名、签发者、受众和过期时间。Admin 再查询 Redis 权威在线状态。直连资源服务时执行相同校验。
- Gateway 负责转发、浏览器来源控制和请求追踪。保留已有 Identity MVC 错误处理和追踪，认证、授权及 Gateway 错误采用统一的 Problem Details 契约。

## 2. 接口与会话

| 操作 | Portal | Admin |
| --- | --- | --- |
| 登录 | `POST /api/v1/auth/portal/login` | `POST /api/v1/auth/admin/login` |
| 刷新 | `POST /api/v1/auth/portal/refresh` | `POST /api/v1/auth/admin/refresh` |
| 退出 | `POST /api/v1/auth/portal/logout` | `POST /api/v1/auth/admin/logout` |
| 当前身份 | `GET /api/v1/auth/portal/me` | `GET /api/v1/auth/admin/me` |
| Refresh Cookie | `portal_refresh_token`，Path 为 `/api/v1/auth/portal` | `admin_refresh_token`，Path 为 `/api/v1/auth/admin` |

登录使用中国大陆 11 位手机号和密码，MySQL 保存 Argon2id 密码哈希。手机号不存在、密码错误或账号禁用时，统一返回凭证无效。Admin 验证登录凭证成功后再判断后台角色。登录和刷新返回 Access Token、有效期及用户摘要。摘要包含账号 ID 和脱敏手机号，Admin 的 `me` 另外返回角色。`GET /api/v1/auth/jwks` 发布资源服务可用的验签公钥。

Access Token 采用 RS256 JWT，有效期 600 秒，包含账号、会话、应用受众及身份版本等信息，前端保存在内存。Refresh Token 为不透明随机凭证，空闲期限 7 天，绝对期限 30 天。MySQL 只保存 Refresh Token 哈希和轮换记录。浏览器通过 HttpOnly Cookie 持有凭证。生产环境启用 Secure，默认 SameSite=Lax，省略 Domain。涉及 Cookie 的认证接口校验浏览器来源。

## 3. 退出与撤权

- **Portal 退出**。当前会话及 Refresh Token 立即撤销，对应 Cookie 被清除。已签发的 Access Token 保留原定剩余有效期，最多 10 分钟。
- **Admin 退出**。确认当前会话已撤销、Refresh Token 已失效且 Redis 在线状态会拒绝旧 Access Token 后，才清除 Cookie 并返回成功。无法确认时返回 `503 AUTH_STATE_UNAVAILABLE`，保留 Cookie 供同一退出操作重试。数据库已撤销但 Redis 尚未确认时，重试继续确认撤销结果。
- **其他身份变更**。账号禁用或后台角色撤销通过同事务 Outbox 同步，从事务提交到 Admin 拒绝旧权限的目标仍为 5 秒，按正常运行条件验收。Portal 账号禁用后不可登录或刷新，旧 Access Token 受 10 分钟有效期约束。后台角色撤销不影响普通用户的 Portal 会话。
- **后台错误处理**。失去后台资格返回 `403 ADMIN_ACCESS_REVOKED`，前端清理后台登录态。已撤销的会话凭证返回 `401 UNAUTHENTICATED`。会话仍有效且仅令牌版本过旧时返回 `401 ACCESS_TOKEN_STALE`，允许刷新。普通业务 `403 FORBIDDEN` 保留登录态。在线状态缺失或不可用时拒绝访问并返回 `503 AUTH_STATE_UNAVAILABLE`。

## 4. 轮换与多标签页并发

服务端锁定 Refresh Token 所属会话，验证应用、账号启用状态、凭证版本以及会话的撤销状态、空闲期限和绝对期限。通过后再按凭证是否已消费分支。首次消费有效 Refresh Token 时，在同一数据库事务内标记已消费、保存唯一后继的哈希并更新空闲期限，事务成功后才发出带新 Cookie 的响应。宽限期从该令牌首次成功轮换的事务提交时刻起算。

### 4.1 Portal

| 旧凭证状态 | 结果 |
| --- | --- |
| 未消费且有效 | 返回 `200` 与新的 `AuthSession`，通过 `Set-Cookie` 写入唯一后继 Refresh Token。 |
| 已消费，距离首次成功轮换提交不超过 10 秒（含 10 秒） | 返回 `200` 与新的 `AuthSession`，为本次请求签发新的 Access Token，响应中省略 `Set-Cookie`。保留当前会话及轮换结果，空闲期限、绝对期限和宽限期均保持原值。 |
| 已消费，距离首次成功轮换提交超过 10 秒 | 撤销该令牌所属会话及其全部 Refresh Token，记录安全审计，返回 `401 REFRESH_TOKEN_REPLAYED`。 |

各 Portal 标签页正常处理自己的 `200` 响应。单个 HTTP 客户端实例仍合并并发刷新，并在成功后最多重试原请求一次。自动续期返回的 `user.id` 与原请求所属账号不一致时，清理本地旧状态并终止原请求。Portal 刷新由后端判定与浏览器 Cookie 共同处理，前端不实现跨标签页锁、结果广播或等待状态机。发起退出或切换账号的标签页要丢弃本地旧会话的迟到响应，并清理旧私有数据。其他标签页在后续续期失败时清理各自状态。

宽限期内服务端不能从旧凭证判断提交者是否为同一浏览器。若旧凭证已泄露，持有者仍可在窗口内换取有效期为 600 秒的 Access Token。本项目接受这一 Portal 风险，以避免正常并发使用户退出。宽限期没有新的 Refresh Token，也不延长会话续期资格。若首次带 `Set-Cookie` 的响应未送达，后续重复响应只能提供 Access Token，客户端可能在后续续期时需要重新登录。重放处置只撤销所属会话，已签发的 Portal Access Token 按原到期时间失效。[RFC 9700 §4.14.2](https://www.rfc-editor.org/rfc/rfc9700.html#section-4.14.2)

### 4.2 Admin

未消费且有效的 Refresh Token 正常轮换。已消费的 Refresh Token 在首次成功轮换提交后 3 秒内（含 3 秒）返回 `409 REFRESH_ALREADY_ROTATED`，保留会话、Cookie 和原宽限期，不签发新凭证。超过 3 秒返回 `401 REFRESH_TOKEN_REPLAYED`，撤销所属会话并同步在线状态，Outbox 继续投递未完成的事件。账号、后台身份或会话已失效时照常拒绝。

Admin 前端通过跨标签页互斥和 `BroadcastChannel` 共用刷新结果。收到 `409` 后进入有上限的等待，等待中保留登录态且不重发旧刷新请求。无法恢复时提示重新登录。退出或切换账号后丢弃旧会话迟到的响应与广播。

## 5. 验收条件

- Portal 并发使用同一旧 Refresh Token 时只产生一个后继。恰好 10 秒的重复请求返回 `200` 和有效的新 Access Token，省略 `Set-Cookie`，会话期限和宽限期保持原值。
- Portal 宽限期外使用旧凭证返回 `401 REFRESH_TOKEN_REPLAYED`。失效状态优先于宽限期，账号禁用、版本失效、会话撤销或到期时均不签发凭证。其他设备及另一应用的会话保持有效。
- 两个 Portal 标签页并发恢复或续期时各自消费响应，验证浏览器保留唯一后继 Cookie。发起退出或切换账号的标签页不采纳旧会话的迟到结果。
- Admin 宽限期采用 3 秒和 `409`，前端在并发刷新时共用结果。Admin 退出成功后的旧 Access Token 会被服务端拒绝。Redis 状态无法确认时，Admin 拒绝受保护请求，退出接口也不返回成功。
- 两端使用独立的 Cookie 和 Bearer 凭证。Portal 退出后，旧 Access Token 按原定有效期失效。Admin `me` 返回后台角色。注册保留为后续草案。
