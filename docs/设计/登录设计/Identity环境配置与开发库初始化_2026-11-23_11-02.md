# Identity 环境配置与开发库初始化

假设你刚拉下项目，本机已有 MySQL 服务。现在你要从一个空库开始启动 `identity-service`，最后查到一个普通账号和一个带 `SUPER_ADMIN` 角色的测试账号。

## 一、环境配置怎么设计

Spring Boot 的 Profile 决定 Identity 读取哪一组数据库连接配置和哪些 Flyway 脚本。`application.yml` 提供共用设置，包括 HTTP 端口 `8081`、Flyway 正式迁移目录 `classpath:db/migration` 和 MySQL 连接时区 `+00:00`。连接时区固定为 UTC，因此数据库给账号创建时间和授权时间填默认值时，各环境都按同一时区记录。见[共用配置](../../../xihu-backend-complete-scaffold-v0.2/xihu-backend-blueprint/backend/identity-service/src/main/resources/application.yml)。

| Profile | 用途 | 数据库连接环境变量 | Flyway 启动时加载 |
| --- | --- | --- | --- |
| `dev` | 本地开发和手动验证 | `IDENTITY_DEV_DB_URL`、`IDENTITY_DEV_DB_USERNAME`、`IDENTITY_DEV_DB_PASSWORD` | `db/migration`、`db/seed` |
| `test` | 使用独立数据库运行集成测试 | `IDENTITY_TEST_DB_URL`、`IDENTITY_TEST_DB_USERNAME`、`IDENTITY_TEST_DB_PASSWORD` | `db/migration`、`db/seed` |
| `prod` | 生产运行 | `IDENTITY_PROD_DB_URL`、`IDENTITY_PROD_DB_USERNAME`、`IDENTITY_PROD_DB_PASSWORD` | `db/migration` |

每次启动选择一个 Profile，每个环境指向各自的库。这样集成测试和本地手动操作就能各用各的数据。仓库中的 YAML 保存环境变量名，实际 URL、用户名和密码由启动 Identity 的进程提供。

**第一次启动时，先由人创建空数据库，再由 Flyway 创建库里的表和数据。** 正式迁移建立三张 Identity 表，并写入 `SUPER_ADMIN` 角色定义。种子迁移写入两条测试账号，并将其中一个账号与该角色关联。Flyway 将每个已执行的版本记入 `flyway_schema_history`，后续启动只应用尚未执行的版本。`prod` 的首位管理员通过受控预置流程创建，已放到后端 README。见[建表与种子的设计](账号基础数据建模/账号基础数据建模_2026-11-22_16-20.md#5-初始化和一致性)、[生产预置入口](../../../xihu-backend-complete-scaffold-v0.2/xihu-backend-blueprint/README.md#identity-数据库与首位管理员)和 [Spring Boot 的 Flyway 初始化说明](https://docs.spring.io/spring-boot/how-to/data-initialization.html#howto.data-initialization.migration-tool.flyway)。

## 二、在 Windows 上初始化开发库

下面的示例使用本机 `127.0.0.1:3306` 的 MySQL 8.0.17 或以上版本、JDK 17 或以上版本、Maven 和 PowerShell 7.1 或以上版本。库名用 `identitydev`，让读者可以照着教程逐条执行。如果你的 MySQL 端口有改动，后面的 mysql 命令和 JDBC URL 都填实际端口。

### 第 1 步 · 确认 MySQL 在运行

打开 PowerShell，运行下面三条命令看工具版本。

```powershell
mysql --version
java -version
mvn -v
```

`mysql --version` 显示的是客户端版本。接下来用本机 MySQL 的管理员账号实际连一次，`--password` 会在下一行提示输入密码。示例里的 `root` 只用于创建开发库和数据库用户。

```powershell
mysql --host=127.0.0.1 --port=3306 --user=root --password
```

看到 `mysql>` 就说明已经连上服务器。在这个提示符下输入 `SELECT VERSION();`，确认服务端版本。连接被拒绝时，先在 Windows「服务」里确认 MySQL 服务正在运行，再核对实例的端口。见 [MySQL 客户端连接说明](https://dev.mysql.com/doc/refman/8.0/en/connecting.html)。

### 第 2 步 · 建一个空库和专用的开发用户

继续在 `mysql>` 下执行以下 SQL。先把 `ReplaceWithYourLocalDbPassword` 换成你选的开发库密码，后面启动服务时还要用到它。

```sql
CREATE DATABASE identitydev
    CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_bin;

CREATE USER 'identity_dev_app'@'127.0.0.1'
    IDENTIFIED BY 'ReplaceWithYourLocalDbPassword';

GRANT ALL PRIVILEGES ON identitydev.* TO 'identity_dev_app'@'127.0.0.1';

USE identitydev;
SHOW TABLES;
```

第一次执行时，`SHOW TABLES` 应显示空结果。这三个操作分别建立库、建立用户、授予该用户对开发库的权限。Flyway 启动时需要在这一个库里建表并写入种子，因此这里授予的是 `identitydev` 的库级权限。已有同名库或用户时，先确认它属于这个项目，再用原连接信息继续。执行 `exit` 回到 PowerShell。见 [MySQL 创建账号和授权说明](https://dev.mysql.com/doc/refman/8.0/en/creating-accounts.html)。

**这里的密码是 MySQL 用户 `identity_dev_app` 的连接密码。** 第 5 步查到的手机号和测试密码是应用账号的凭证，分别用在不同的入口。

### 第 3 步 · 配置环境变量，打包 Identity

回到 PowerShell，进入包含父 `pom.xml` 的 `backend` 目录。下面使用当前工作区路径，仓库放在其他位置时替换路径前半段即可。

```powershell
Set-Location -LiteralPath 'D:\sword_shield_web\sword_shield_web\xihu-backend-complete-scaffold-v0.2\xihu-backend-blueprint\backend'

$env:IDENTITY_DEV_DB_URL = 'jdbc:mysql://127.0.0.1:3306/identitydev'
$env:IDENTITY_DEV_DB_USERNAME = 'identity_dev_app'
$env:IDENTITY_DEV_DB_PASSWORD = Read-Host '输入刚为 identity_dev_app 设置的密码' -MaskInput

mvn -B -pl identity-service -am -DskipTests package
```

输入时 PowerShell 显示星号，回车后将密码交给当前终端的环境变量。后面要从**同一个 PowerShell 窗口**启动 Java，Java 才能继承这些变量。最后一条命令会打包 `identity-service` 及所需模块，成功时会看到 `BUILD SUCCESS`，产物位于 `identity-service/target`。见 [PowerShell 密码输入](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/read-host)和[环境变量作用域](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_environment_variables)。

### 第 4 步 · 启动 Identity，让 Flyway 初始化

在刚才的 PowerShell 窗口运行下面的命令。

```powershell
java -jar .\identity-service\target\identity-service-0.1.0-SNAPSHOT.jar --spring.profiles.active=dev
```

启动日志里先找 `dev` Profile，再找 Flyway 的迁移日志。对一个全新的库，Flyway 会先执行表结构和角色定义迁移，再执行测试账号种子迁移。看到 `Started IdentityApplication` 后，保持这个窗口打开，再开一个 PowerShell 窗口检查服务状态。

```powershell
(Invoke-RestMethod 'http://localhost:8081/actuator/health').status
```

正常会返回 `UP`。服务确认启动后，下一步查数据库，确认你连对了库、脚本也确实跑过。

**如果你从 IDEA 启动**，打开运行配置，选 `IdentityApplication`，在 **Program arguments** 填 `--spring.profiles.active=dev`，在 **Environment variables** 里填第 3 步的三个变量。运行配置对启动的 Java 进程生效。已经打开的 IDEA 实例需要在自己的运行配置中取得这些值。

### 第 5 步 · 查库，确认两份迁移和两个账号

用开发数据库用户连到本次创建的库，按提示输入它的 MySQL 密码。

```powershell
mysql --host=127.0.0.1 --port=3306 --user=identity_dev_app --password --database=identitydev
```

在 `mysql>` 中执行。

```sql
SELECT DATABASE(), CURRENT_USER();
SHOW TABLES;

SELECT version, description, success
FROM flyway_schema_history
WHERE version IS NOT NULL
ORDER BY installed_rank;

SELECT a.phone, a.status, r.code AS role_code
FROM identity_account a
LEFT JOIN identity_account_role ar ON ar.account_id = a.id
LEFT JOIN identity_role r ON r.id = ar.role_id
WHERE a.phone IN ('13800000001', '13800000002')
ORDER BY a.phone;
```

你应该看到这些结果。

- 当前数据库是 `identitydev`，连入的是刚创建的数据库用户。
- 有 `identity_account`、`identity_role`、`identity_account_role` 和 `flyway_schema_history` 四张表。
- `202611221620` 和 `202611221621` 都执行成功，本次的建表和播种各有一条版本记录。

| 测试手机号 | `status` | `role_code` | 对应的应用测试密码 |
| --- | --- | --- | --- |
| `13800000001` | `ENABLED` | `NULL` | `LocalPortal-Only!2026` |
| `13800000002` | `ENABLED` | `SUPER_ADMIN` | `LocalAdmin-Only!2026` |

查询能看到账号状态和授权，数据库里的密码列保存的是哈希。本阶段以健康检查和查库验收，登录页面和真实验密链路随登录功能交付。下次对同一个库启动 Identity 时，Flyway 根据已成功的版本记录跳过这两份迁移，测试账号仍是原来的两条。

### 卡住时先看这三处

| 看到什么 | 先查哪里 |
| --- | --- |
| `Communications link failure` 或连接被拒绝 | 用第 1 步的 mysql 命令核对服务和端口，确认 JDBC URL 指向同一个实例。 |
| `Unknown database 'identitydev'` | 用 MySQL 管理员账号确认第 2 步在同一个实例成功建库。 |
| `Access denied` 或缺少 `IDENTITY_DEV_DB_*` | 先用第 5 步的 mysql 命令核对开发库用户和密码，再看启动 Java 的终端或 IDEA 运行配置是否拿到了三个变量。 |

用完后在运行 Identity 的窗口按 `Ctrl+C` 停止服务，关掉这个 PowerShell 窗口即可结束本次进程环境。
