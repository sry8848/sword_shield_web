# 登录设计变更记录

## 2026-11-21 23:14

- 上一版为[业务设计 v1.0](登录设计_2026-11-09_15-26.md)，本版为[业务设计 v1.1](登录设计_2026-11-21_23-14.md)。
- 明确 Portal 与 Admin 的退出成功语义，以及后台角色撤销只影响后台访问。
- 增加并发刷新宽限期及窗口外重放的处置范围。
- 本期 Admin 身份接口返回账号及角色，权限码由后续 RBAC 模块提供。见[技术设计](登录与会话技术设计_2026-11-21_23-14.md)。

## 2026-11-25 10:40

- 业务设计从 [v1.1](登录设计_2026-11-21_23-14.md)更新为 [v1.2](登录设计_2026-11-25_10-40.md)。技术设计从 [2026-11-21 版](登录与会话技术设计_2026-11-21_23-14.md)更新为 [2026-11-25 版](登录与会话技术设计_2026-11-25_10-40.md)。
- Portal 在首次成功轮换提交后 10 秒内（含 10 秒）再次收到已消费的 Refresh Token 时，返回 `200` 和新的 Access Token。首次轮换独占后继 Refresh Token 的写入及 `Set-Cookie`。超过宽限期的重放撤销所属会话。
- 阶段三取消任务 3.5 的 Portal 跨标签页互斥、广播及等待流程，双标签页行为移入 3.4 验收。Admin 沿用已评审的 3 秒宽限期、`409` 和跨标签页刷新协调。
- 接受 Portal 旧 Refresh Token 在宽限期内仍可兑换短期 Access Token 的风险。该取舍减少正常并发导致的退出，并保留后端的单次轮换与窗口外重放处置。

## 2026-11-25 Admin 重新设计（v1.3）

- 按最新确认的三固定角色、纯 Redis Spring Session、Gateway ForwardAuth 更新现行[业务设计](登录设计_2026-11-25_10-40.md)与[技术设计](登录与会话技术设计_2026-11-25_10-40.md)。
- 删除 Admin JWT/Refresh、3 秒宽限期、409、跨标签页同步及 Redis 状态镜像/Outbox 和 5 秒撤权目标；Portal 规则保持不变。
- 历史版本和既有 SQL/代码不重写；未确认的 Session 时长和部署问题保留待确认。
